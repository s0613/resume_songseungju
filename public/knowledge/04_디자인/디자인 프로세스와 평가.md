# 디자인 프로세스와 평가

> 한 줄 정의
> 디자인 품질을 감각이 아니라 절차로 담보하는 방법 — 방향 선언 → 시안 분기 → 선택 → 구현 → 평가의 루프와 각 단계의 판정 기준.

## 1. 방향 선언 — "클린·미니멀" 금지

- "클린하고 미니멀하게"는 방향이 아니라 무방향의 다른 말이다. 구체적 스타일 방향을 하나 선언한다: 에디토리얼 / 네오브루탈리즘 / 글래스모피즘 / 벤토 / 스크롤리텔링 / 스위스 / 레트로퓨처 / 다크·라이트 럭셔리 …
- 레퍼런스 2~3개에서 **DNA를 값으로 추출**한다: 정확한 hex · 서체 · 간격 스케일 · radius. "이런 느낌"이 아니라 숫자.
- 다크 모드를 자동 기본값으로 삼지 않는다 — 제품이 원하는 방향을 고른다.

## 2. 시안 분기 — 텍스트가 아니라 시각물로 결정

- 방향이 불확실하면 극단이 다른 2~3안(예: 역동형·절제형·균형형)을 먼저 만들어 보여준다. 텍스트 설명으로는 방향 합의가 안 된다.
- 거부된 방향은 **봉인 기록**한다 — 같은 방향을 다시 제안하는 것이 최다 반복 실수다. 다음 시안은 반대 방향에서 시작한다.
- 승인된 DNA(색·서체·간격 값)도 기록해 다음 사이클의 입력으로 재사용한다.

## 3. 구현 — 토큰 선언이 첫 커밋

- 코드 첫 줄 전에 토큰을 선언한다 ([[디자인 시스템]]). 구현 중 "일단 하드코딩"이 체계 붕괴의 시작.
- 구현 후 레퍼런스와 나란히 비교한다 — 스크린샷을 옆에 두고 DNA 값을 대조.

## 4. 평가 — 순서대로, 싼 것부터

| 단계 | 방법 | 잡는 것 |
|------|------|--------|
| 5초 테스트 | 첫 화면 5초 노출 후 "무슨 화면? 뭘 해야?" | 계층·주인공 실패 |
| 휴리스틱 평가 | 닐슨 10항목 점검 (아래) | 일관성·피드백·복구 결함 |
| 접근성 검사 | 자동 스캔 + 키보드 순회 + 대비 측정 | WCAG 위반 |
| 스크린샷 회귀 | 320/768/1440 캡처 비교 | 의도치 않은 시각 변경 |
| 사용성 테스트 | 5명 · 태스크 기반 · 유도 질문 금지 | 실제 수행 실패 (5명이면 문제 ~85% 발견) |

## 닐슨 휴리스틱 압축판

시스템 상태 가시성 · 현실 세계 일치 · 사용자 통제(undo) · 일관성 · 오류 예방 · 재인 우선(기억 강요 금지) · 유연성(숙련자 지름길) · 미니멀리즘 · 오류 복구 지원 · 도움말.
→ 실행 점검은 [[디자인-체크리스트]].

## AI에게 디자인을 맡길 때

- 컨텍스트로 명시할 것: 스타일 방향 1개([[디자인 스타일 카탈로그]]에서 선택) · 토큰/DNA 값 · 금지 목록(봉인된 방향 + [[UI 시각 체계]]의 템플릿 안티패턴).
- "예쁘게" · "모던하게"는 프롬프트가 아니다 — 기본값 템플릿이 나온다.
- 산출물 평가는 위 평가 표를 그대로 적용한다. AI 산출이라고 기준을 낮추지 않는다.
- 스타일명과 토큰만으로 생성하지 않는다. 실제 사용자·과업·카피·데이터·필수 상태를 먼저 잠그고 [[AI 티 없는 웹디자인 원칙]]의 디자인 계약과 냄새 점검을 통과한다.
