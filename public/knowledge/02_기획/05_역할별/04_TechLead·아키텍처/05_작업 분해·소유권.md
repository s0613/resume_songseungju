# 작업 분해·소유권

> 작업을 수직 슬라이스와 specialist 책임으로 나누고 병렬 수정 파일이 겹치지 않게 한다. 분해 결과는 **WBS·일정계획과 정합**해야 한다 — WBS의 마일스톤이 지불 조건이므로, 슬라이스 완료가 어느 마일스톤 산출물에 기여하는지 표시한다 ([[SI 수주와 범위 관리]]).

## 완료·재개 계약

- 같은 RUN_ID에서 입력보다 새 Result Card가 있으면 완료 역할을 재호출하지 않는다.
- Result Card 필수 고정 계약: `# {Role} Output — …`, `## 변경 파일`, `## 알려진 제약 / 후속 작업`.
- 변경 파일이 비었거나 소유권을 벗어나거나 요구를 막는 제약이 남으면 재디스패치한다.
- 구현 중 발견한 범위 밖 작업(추가 화면·연동·이관)은 구현하지 말고 CR 후보로 보고한다.
- 자동 재디스패치는 최대 2회이며 이후 사람에게 남은 이슈와 선택지를 에스컬레이션한다.
