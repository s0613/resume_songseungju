# SI·문서화 기획 가이드

> SI·문서화의 임무는 계약 범위와 실제 수행 결과를 살아 있는 문서·추적표·검수 증거·인수인계로 연결해 발주사가 독립 운영할 수 있게 하는 것이다.

## 활성화 조건

- 외부 발주사에게 계약 산출물을 납품한다.
- 마일스톤 검수, 대금 지급, SLA, 하자보수 조건이 있다.
- 발주사·운영자 교육과 기술·계정·자산 인계가 필요하다.
- 요구사항부터 구현·테스트·승인까지 추적 가능한 종료 근거가 필요하다.

## 필수 입력

| 입력 | 최소 조건 | 없을 때 |
|---|---|---|
| RFP·제안·계약 기준본 | 범위, 범위 밖, 산출물, 검수·대금 조건 | 착수 차단·계약 확인 |
| 요구사항·변경 원장 | ID, 승인자, 적용 버전 | RTM 작성 차단 |
| WBS·마일스톤 | Owner, 일정, 의존성 | 납품 시점 재협의 |
| 설계·구현·테스트 원본 | 실제 파일·버전·증거 | 확인 불가로 표시 |
| 발주사·운영 담당자 | 검토·승인·인수 주체 | 서명·교육 일정 차단 |

## 결정 순서

1. [[01_계약 산출물·마일스톤]]에서 계약 기준본과 전달·검수·대금 조건을 고정한다.
2. [[02_문서 10종 계획]]의 작업 개요부터 도메인 맵까지를 단계마다 갱신하는 **살아 있는 10개 문서**로 운영한다.
3. [[03_RTM·검수 계획]]으로 요구↔설계↔구현↔테스트↔발주사 검수를 관통시킨다.
4. [[04_매뉴얼·교육·인수인계]]에서 시스템·운영·사용자 매뉴얼, 교육, 자산 인계를 계획한다.
5. [[05_변경·SLA·유지보수]]로 CR, 서비스 수준, 하자보수와 유상 유지보수 경계를 합의한다.
6. [[90_SI·문서화 완료 체크리스트]]를 실행하고 [[99_SI 납품 확인 템플릿]]으로 인수 확인을 받는다.

## 산출물과 소비자

| 산출물 | 소비자 | 요청 행동 |
|---|---|---|
| 계약 산출물·마일스톤 원장 | PM·발주사 책임자 | 범위·검수·대금 승인 |
| 살아 있는 문서 10종·RTM | 구현·QA·발주사 검수자 | 갱신·검증·서명 |
| 매뉴얼·교육·인수인계 | 운영자·유지보수자 | 자립 확인 |
| 납품 확인 | 발주사·정산 담당 | 인수·잔금·종료 처리 |

## 역할 경계

- SI·문서화는 PM의 범위 결정, 아키텍트의 설계, QA의 판정을 대신하지 않는다.
- 확인하지 않은 수치·기능·테스트를 사실처럼 쓰지 않는다.
- 검수 직전에 문서를 역으로 꾸미지 않고 각 단계의 승인본과 실제 소스에서 갱신한다.
- 계약 밖 요청은 조용히 포함하지 않고 [[05_변경·SLA·유지보수]]의 CR로 처리한다.
- 납품·인수 층위를 섞지 않는다 — Release·운영은 시스템 운영 상태의 기술적 이관, SI·문서화는 계약 산출물·자산의 납품, 고객·업무책임은 발주사의 인수 확인·서명을 맡는다.
- 발주사 지연(자료·결정·검수)은 발생 즉시 날짜·영향을 기록한다.

## 진입·종료 게이트

**진입:** 계약 기준본, 산출물 목록, 마일스톤·검수·대금 조건, Owner·승인자가 식별됐다.

**종료:** 문서 10종이 현재 상태이고, RTM·매뉴얼·교육·인수인계가 실제 버전과 일치하며, 미해결·예외·지원 경계가 포함된 발주사 인수 기록이 있다.
