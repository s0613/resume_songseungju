# UX·UI디자인 완료 체크리스트

## 현업 인터뷰·업무 분석

- [ ] 주 사용 부서·핵심 업무·실제 처리 방식이 인터뷰 근거로 연결됐다.
- [ ] 관찰·인용·수치와 해석·아이디어가 분리됐다.
- [ ] AS-IS 마찰뿐 아니라 반례·비대상 업무도 기록됐다.
- [ ] 계약 범위에서 해결하는 마찰과 해결하지 않는 마찰(OUT/CR 후보)이 구분됐다.
- [ ] 미확정 업무 규칙에 발주사 확인 방법·합의 결과·Owner·기한이 있다.
- [ ] 발주사 지연(인터뷰 미섭외·자료 미제공)이 있었다면 날짜·영향이 기록됐다.

## 정보구조·흐름 — 메뉴구조도

- [ ] 콘텐츠·객체의 현업 용어와 권한이 일관된다.
- [ ] 사이트맵이 메뉴구조도/프로그램 목록 납품본으로 제출 가능한 상태다.
- [ ] 핵심 흐름에 진입·분기·성공·실패·복구가 있다.
- [ ] 뒤로가기·취소·새로고침·세션 만료 시 동작이 정의됐다.
- [ ] 요구 ID가 Flow와 화면으로 추적된다(RTM 갱신).
- [ ] API·정책 미결을 화면에서 임의로 가정하지 않았다.

## 화면·상태 — 화면정의서

- [ ] 모든 화면에 목적·주 액션·권한·승인 시안(버전·승인일)이 있다.
- [ ] 기본·로딩·빈·오류·권한 없음·완료 상태가 정의됐다.
- [ ] 오류 메시지는 원인 범위와 다음 행동을 제공한다.
- [ ] 파괴적 행동은 확인·되돌림·권한이 설계됐다.
- [ ] 긴 콘텐츠·빈 값·대량 데이터 스트레스 케이스가 발주사 실데이터 기준으로 있다.
- [ ] 화면정의서가 검수 근거로 제출 가능하다 — 상태 정의가 테스트케이스와 대응한다.

## 방향·토큰 — 시안 승인

- [ ] 시안 수정 라운드 횟수(예: 2회)가 착수 전 합의·기록됐다.
- [ ] 라운드별 피드백·반영·버전이 기록됐고, 초과 요청은 CR로 회부됐다.
- [ ] 발주사 승인자·승인 시안·버전·일시가 서면/메일 근거와 함께 기록됐다.
- [ ] 색·타입·간격·레이아웃이 정확한 토큰으로 고정됐다.
- [ ] 새 raw 값·화면 전용 테마가 없거나 명시적으로 승인됐다.
- [ ] hover·focus·active·disabled 상태가 있다.

## 접근성·반응형

- [ ] 접근성 기준(WCAG/KWCAG·인증 여부)과 지원 브라우저·기기가 계약 근거로 확정됐다.
- [ ] 본문 4.5:1, UI 3:1 등 적용 기준과 측정값이 있다.
- [ ] 키보드 순서·포커스 진입·복귀·상태 알림이 정의됐다.
- [ ] 색만으로 정보를 전달하지 않는다.
- [ ] prefers-reduced-motion과 터치 대상 기준이 있다.
- [ ] 320·375·768·1024·1440px의 배치·오버플로 규칙이 있다.
- [ ] 자동 검사와 사람 검증의 명령·절차·증거 형식이 테스트결과서에 넣을 수 있게 있다.

## S-skills 인계

- [ ] `design-handoff.md`에 `source`, `brand`가 있다.
- [ ] 필수 CSS 변수 9개와 `## 레이아웃 패턴`이 정확히 있다.
- [ ] Frontend가 한 글자도 바꾸지 않아야 할 값이 명확하다.
- [ ] 상태·접근성·반응형 확장 계약의 원본 경로가 연결됐다.
- [ ] 미수행 검사는 `미수행: 이유·위험`으로 표시됐다.
