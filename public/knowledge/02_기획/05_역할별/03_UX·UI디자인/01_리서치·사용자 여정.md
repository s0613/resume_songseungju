# 리서치·사용자 여정

> 외주 프로젝트의 리서치는 **현업 인터뷰·AS-IS/TO-BE 업무 분석**이다. 발주사 담당자의 말보다 현업의 실제 업무 처리 방식을 우선하고, 관찰·인용·수치와 해석·아이디어를 분리한다. 여기서 확정한 AS-IS/TO-BE가 요구사항정의서와 화면정의서의 근거가 된다.

## 현업 인터뷰 계획

| 항목 | 값 |
|---|---|
| 확인할 질문 | `{이번 인터뷰로 확정할 업무 규칙·예외 1~3개}` |
| 연결 요구 ID | `{OBJ / FR / OUT}` |
| 대상 현업·제외 대상 | `{부서·역할 / 비대상 업무}` |
| 방법 | `현업 인터뷰 / 업무 관찰 / 현행 시스템 로그 / 화면 시연` |
| 대상자·선정 기준 | `{N명 · 해당 업무를 실제 수행하는 사람}` |
| 일정·Owner | `{날짜 · 이름}` |
| 발주사 협조 요청 | `{인터뷰 대상자 섭외·현행 화면 접근 권한 등}` |
| 지연 기록 | `{발주사 일정 미확정·자료 미제공 시 날짜·영향 기록}` |

> [!WARNING] 인터뷰 대상자 섭외·현행 자료 제공은 발주사 의무다
> 지연되면 즉시 기록하고 일정 영향을 공지한다 ([[SI 수주와 범위 관리]] §진행 중 신뢰 관리). 종료 시점 책임 공방의 방어 자료다.

## 질문 가이드

| 확인 목적 | 질문 | 피해야 할 질문 |
|---|---|---|
| 실제 업무 방식 | `마지막으로 이 업무를 처리했을 때 처음부터 보여주세요.` | `이 기능이 있으면 쓰시겠어요?` |
| 장애물·비용 | `어디서 막혔고, 그때 어떻게 처리했나요?` | `이 부분이 불편하시죠?` |
| 현행 우회 | `지금은 어떤 시스템·엑셀·사람으로 해결하나요?` | `새 시스템이 현행보다 낫겠죠?` |
| 예외·빈도 | `이 예외는 한 달에 몇 번 생기고, 누가 어떻게 처리하나요?` | `어떤 기능을 원하세요?` |
