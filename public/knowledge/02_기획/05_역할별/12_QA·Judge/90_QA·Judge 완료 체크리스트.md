# QA·Judge 완료 체크리스트

## 독립성·기준

- [ ] 구현자의 요약이 아니라 원본 요구사항과 실제 산출물을 직접 확인했다.
- [ ] 구현자와 QA 컨텍스트·실행·판정을 분리했다.
- [ ] 모든 필수 요구사항에 관찰 가능한 완료 조건이 있다.
- [ ] 완료 조건·기대값은 착수 전 발주사와 합의된 기준본을 사용했고, 사후 합의 기준이 없다.
- [ ] 완료 조건이 없는 항목을 PASS로 세지 않았다.
- [ ] 대상 버전·commit·환경이 고정됐다.

## 실행·증거

- [ ] 요구사항↔테스트↔결과↔증거가 1:1로 추적된다.
- [ ] 정상·경계·권한·실패·복구·회귀 경로를 위험에 맞게 실행했다.
- [ ] 실제 결과, 로그, 스크린샷 또는 리포트가 대상 버전과 연결된다.
- [ ] 미수행·BLOCKED·범위 밖을 PASS와 분리했다.
- [ ] 결함에 재현 절차, 심각도, Owner, 상태가 있다.
- [ ] 범위 밖 발견을 결함이 아니라 CR 후보로 분리해 회부했다.

## 판정·인계

- [ ] 진입·종료 기준을 사후 완화하지 않았다.
- [ ] Critical·High와 필수 조건 실패를 숨기지 않았다.
- [ ] CONDITIONAL 예외에는 사람 승인자·Owner·기한이 있다.
- [ ] 잔여 위험과 운영 관찰 항목을 Release·운영에 넘겼다.
- [ ] 테스트계획서·테스트케이스·테스트결과서가 납품 가능한 형식으로 정리됐다.
- [ ] 내부 케이스(TC-\*)가 현업 검수 시나리오(US-\*/EX-\*)와 추적된다 ([[시나리오·예외사항 문서 작성법]]).
- [ ] [[99_QA 판정 템플릿]]을 실제 실행 증거로 채웠다.
