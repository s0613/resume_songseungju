# 진입·종료·판정 기준

> 테스트 시작과 종료, 최종 판정을 이해관계자의 분위기가 아니라 사전 합의한 조건으로 결정한다. 이 판정이 발주사 검수(UAT) 회부 여부와 테스트결과서의 결론을 정한다.

## 진입 기준

| 기준 | 확인 방법 | 결과 | 증거·미충족 조치 |
|---|---|---|---|
| 완료 조건이 승인되고 추적 가능하다 | | | |
| 대상 build·commit이 고정됐다 | | | |
| 환경·데이터·권한이 준비됐다 | | | |
| 차단 리뷰 발견이 처분됐다 | | | |
| 알려진 제약·범위 밖이 공유됐다 | | | |

## 종료 기준

| 기준 | 목표 | 실제 | 증거 | 충족 여부 |
|---|---|---|---|---|
| P0·P1 완료 조건 | 100% 실행·PASS | | | |
| Critical·High 결함 | 0건 또는 사람 승인 | | | |
| 회귀 테스트 | 합의 범위 PASS | | | |
| NFR·보안 게이트 | 임계값 충족 | | | |
| 미수행 검사 | 0건 또는 영향·승인 명시 | | | |

## 판정 규칙

| 판정 | 허용 조건 | 다음 행동 |
|---|---|---|
| PASS | 모든 필수 완료 조건이 실행·통과하고 차단 결함이 없음 | Release 게이트·발주사 검수(UAT) 회부 |
| CONDITIONAL | 필수 조건은 통과했고 비차단 예외에 Owner·기한·사람 승인이 있음 | 조건 추적, 검수 회부 시 예외 목록 첨부 |
| FAIL | 하나 이상의 필수 완료 조건 실패 또는 차단 결함 존재 | 수정 후 재검증 |
| BLOCKED | 완료 조건·환경·데이터·권한이 없어 판정 자체가 불가능 | 차단 제거 후 재개 |

> [!IMPORTANT] 완료 조건 없는 PASS 금지
> 요구사항에 검증 가능한 완료 조건이 없으면 판정은 BLOCKED다. QA가 기준을 추정하거나 "대체로 동작"을 PASS로 바꾸지 않는다. 기준·기대값은 착수 전 발주사와 합의된 것만 유효하며, 검수 단계에서의 사후 합의·사후 완화는 분쟁의 원인이다.
