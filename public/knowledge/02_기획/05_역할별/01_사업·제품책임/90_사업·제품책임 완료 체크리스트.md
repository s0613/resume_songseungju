# 사업·제품책임 완료 체크리스트

## RFP·문제 이해

- [ ] RFP 요구가 발주사의 언어로 재서술됐고 발주사가 확인했다.
- [ ] 발주사 조직에서 결재권자·검수자·현업 사용자가 실명으로 식별됐다.
- [ ] AS-IS 업무 방식이 최소 한 건의 현장 근거(인터뷰·샘플)와 연결됐다.
- [ ] RFP에 없지만 발주사가 기대할 항목이 확인 또는 제외 대상으로 분류됐다.
- [ ] 사실과 미확인 가정이 분리되고, 가정마다 착수 전 확인 Owner·기한이 있다.

## 계약 목표·검수 기준

- [ ] 모든 검수 기준(ACC)이 실행하면 PASS/FAIL이 나오는 형식이다.
- [ ] 검수 기준마다 발주사 합의 근거(회의록·메일·서명)가 연결됐다.
- [ ] 사람 판정 항목에 판정자·기준표·수정 라운드 횟수가 있다.
- [ ] 검수 기간 상한(N영업일 내 미회신 시 승인 간주)이 계약에 반영됐다.
- [ ] 하자보수(무상)와 유지보수(유상)의 경계가 합의됐다.

## 견적·범위·지불

- [ ] 견적에 회의·보고, 문서화, 검수 대응, 이관·교육이 명시 항목으로 있다.
- [ ] 리스크 버퍼(15~25% 또는 근거)가 반영됐다.
- [ ] 제외 목록(Out of Scope)과 수정 라운드 횟수가 계약 문구로 있다.
- [ ] 모든 포함 항목이 계약 Must / CR 후보로 구분됐다.
- [ ] 마일스톤마다 납품 산출물·검수 기준·지불 비율이 연결됐다.

## Go/No-Go·CR·승인

- [ ] 수주 Go/No-Go가 조건표 기준으로 판정되고 근거가 결정 카드에 있다.
- [ ] CR 절차(접수→영향 산정→선택지→서면 승인→반영)가 계약에 합의됐다.
- [ ] 단계별 승인 게이트에 필요한 증거와 NO-GO 조건이 있다.
- [ ] 예외 승인에 양측 승인자·만료·잔여 위험이 있다.
- [ ] 발주사 지연(자료·결정)의 기록·통지 규칙이 정해졌다.

## 인계

- [ ] PM·PO·BA에 재서술된 요구·계약 범위·검수 기준이 전달돼 SRS 착수가 가능하다.
- [ ] UX·UI에 현업 사용자·AS-IS 업무·화면정의서 범위가 전달된다.
- [ ] Tech Lead에 고정 제약·계약 범위·연동 불확실성이 전달된다.
- [ ] QA에 검수 기준·판정 방법·검수 일정이 전달된다.
- [ ] 이 문서들이 그대로 검수·계약·분쟁 대응 근거로 쓰일 수 있다.

## 판정

- 판정: `READY / NOT READY / CONDITIONAL`
- 미충족 항목: `{체크박스 또는 없음}`
- 보완 Owner·기한: `{값}`
- 다음 소비자·행동: `{한 문장}`
- 확인자·일시: `{이름 · 날짜}`
