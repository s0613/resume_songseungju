# 사업·제품책임 기획 가이드

> 외주·SI에서 사업·제품책임자는 **수주·계약 책임자**다. 이 RFP를 수주할지(Go/No-Go), 어떤 범위를 얼마에·언제까지 계약할지, 무엇을 계약 밖으로 명시할지, 변경 요청(CR)과 분쟁을 어떻게 예방할지를 최종 결정한다.

## 미션

- RFP·발주사 요구를 재서술해 "발주사가 진짜 사려는 것"을 확정하고, 수주 Go/No-Go를 판단한다.
- 견적(리스크 버퍼 포함)·계약 범위·제외(Out of Scope)·마일스톤=지불 조건·검수 기준을 착수 전에 계약으로 고정한다.
- 범위 변경(CR)·계약 변경·예외 승인에 대한 최종 Accountable Owner가 된다. 분쟁은 사후 대응이 아니라 계약 문구로 예방한다.

## 필수 입력

| 입력 | 확인할 내용 | 없을 때 처리 |
|---|---|---|
| RFP·발주사 요구 원문 | 명시 요구, 숨은 기대, 평가 기준, 예산 규모 | 발주사 질의로 확보. 원문 없는 수주 검토 금지 |
| 발주사 조직·현업 근거 | 결재권자, 검수자, 현업 사용자, AS-IS 업무 방식 | 가정으로 표시하고 착수 전 현업 인터뷰 계획 |
| 자사 수행 역량 | 유사 수행 이력, 가용 인력·기간, 기술 적합성 | 부족분은 Go/No-Go의 No-Go 근거로 기록 |
| 제약 | 납기, 발주사 예산 상한, 법무·보안·규제, 발주사 내부 절차 | 고정 조건과 협상 가능 조건 분리 |
| 기존 계약·이력 | 해당 발주사와의 이전 계약, CR 이력, 분쟁 이력 | 재발 방지 조건을 이번 계약에 반영 |

## 결정 순서

1. [[01_문제·대상사용자 정의]]에서 RFP를 재서술하고 발주사 조직·현업 사용자·AS-IS를 고정한다.
2. [[02_제품 목표·KPI]]에서 계약 목표·검수 기준·SLA를 발주사와 합의 가능한 형태로 정한다.
3. [[03_투자·제약·우선순위]]에서 견적·리스크 버퍼, 계약 범위(포함/제외), 마일스톤=지불 조건을 정한다.
4. [[04_중단·피벗·승인 기준]]에서 수주 Go/No-Go, CR 처리 절차, 단계별 승인 게이트를 정한다.
5. [[90_사업·제품책임 완료 체크리스트]]로 PM이 재해석 없이 요구사항정의서(SRS)에 착수할 수 있는지, 계약 근거가 갖춰졌는지 확인한다.
6. 중요한 선택은 [[99_사업·제품책임 결정 카드 템플릿]]으로 버전과 승인 근거를 남긴다 — 분쟁 시 "합의했다"의 증거다.

## 필수 산출물과 소비자

| 산출물 | 최소 내용 | 다음 소비자의 행동 |
|---|---|---|
| RFP 재서술·발주사 정의 | 문제 재서술, 결재·검수·현업 구조, AS-IS | PM이 요구사항정의서(SRS) 범위를 작성 |
| 계약 목표·검수 기준 합의 | 검수 기준, SLA, 검수 기간 상한, 판정법 | PM이 완료 조건을 만들고 QA가 테스트계획 수립 |
| 견적·범위 결정 | 견적 내역·버퍼, 포함/제외, 마일스톤=지불 조건 | Tech Lead가 해법과 작업 규모를 계약 안으로 제한 |
| Go/No-Go·CR·승인 기준 | 수주 판단 근거, CR 절차, 단계 승인 게이트 | Release·고객 책임자가 검수·이관 판단 |

산출물은 [[외주 개발 산출물]]의 계약 첨부 목록과 연결된다: 이 역할의 결정이 제안서·계약서·산출물 목록(deliverable list)의 원본이다.

## 역할 경계

- 이 역할은 **수주할지·어떤 범위를·얼마에·어떤 조건으로 계약할지**를 결정한다.
- 요구사항정의서(SRS)·WBS·RTM 작성은 PM·PO·BA의 책임이다.
- 화면정의서(스토리보드)의 구조·비주얼은 UX·UI의 책임이다.
- 기술 스택·API정의서·ERD는 Tech Lead의 책임이다.
- 테스트결과서의 PASS/FAIL 판정은 QA·Judge의 책임이다.
- 발주사 검수 서명과 계약상 인수는 고객·업무책임자의 별도 결정이다. 같은 사람이 겸임해도 기록은 분리한다.

## 진입 게이트

- [ ] RFP·발주 요청 또는 계약 변경 검토 요청이 있다.
- [ ] 수주·계약에 대한 최종 결정권자 한 명이 지정됐다.
- [ ] 발주사 요구 원문(RFP·회의록·메일) 최소 한 건 또는 `원문 없음` 상태가 명시됐다.

## 종료 게이트

- [ ] 발주사의 문제·현업 사용자·AS-IS가 한 문단으로 재서술된다.
- [ ] 검수 기준·SLA에 판정법·검수 기간 상한이 있고 발주사 합의 상태가 표시됐다.
- [ ] 견적·버퍼·포함/제외·마일스톤=지불 조건·CR 절차가 명시됐다.
- [ ] 미결 사항마다 Owner와 결정 기한이 있고, 발주사 측 미결은 지연 기록 대상으로 표시됐다.
- [ ] PM·PO·BA가 이전 대화를 재구성하지 않고 요구사항정의서(SRS)를 시작할 수 있다.
- [ ] 이 문서들이 그대로 **검수·계약 근거**로 쓰일 수 있다.
