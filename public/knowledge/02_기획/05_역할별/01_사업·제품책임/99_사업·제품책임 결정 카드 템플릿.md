# 사업·제품책임 결정 카드 템플릿

> 한 카드에는 하나의 수주·계약 결정만 기록한다. 결과가 아니라 당시 이용 가능한 근거와 책임을 남긴다 — 이 카드가 분쟁 시 "그때 이렇게 합의·판단했다"의 증거다.

```markdown
# BIZ-DEC-{NNN}: {결정 제목}

status: Proposed | Approved | Rejected | Superseded
owner: {Accountable Owner 한 명}
reviewer: {역할·이름}
approver: {역할·이름 — CR·계약 변경이면 발주사 승인자 병기}
decision-date: {YYYY-MM-DD}
effective-until: {날짜 또는 재검토 조건}
supersedes: {없음 또는 이전 결정 ID}
related-contract: {계약·CR·회의록 링크}
related-requirements: {SRS FR/NFR/OUT ID}

## 결정이 필요한 맥락
{RFP·발주사 요청, 계약상 계기, 결정하지 않을 때의 비용·분쟁 위험}

## 계약 목표와 제약
- 검수 기준·SLA: {ACC/SLA ID}
- 계약 상한: {금액·납기·인력}
- 고정 제약: {법무·보안·발주사 절차·계약 조항}

## 검토한 선택지

| 선택지 | 계약 이행 영향 | 일정·비용 | 분쟁·검수 위험 | 발주사 수용 가능성 | 되돌림 비용 |
|---|---|---|---|---|---|
| A. {선택지} | | | | | Two-way / One-way |
| B. {선택지} | | | | | |

## 결정
{선택한 방향과 명시적 범위 — 포함·제외를 계약 문구 수준으로}

## 선택 이유와 근거
- {RFP·회의록·발주사 확인 근거}
- {대안 탈락 이유}

## 결과와 영향
- 포함: {항목}
- 제외 (Out of Scope): {항목}
- 계약·견적·일정 변경: {CR·계약 변경 여부}
- 영향받는 역할·산출물: {역할 → 변경 행동, 갱신할 SRS·WBS·RTM}
- 알려진 잔여 위험: {위험}

## 재검토·에스컬레이션 조건
- 재협상 트리거: {범위 밖 요청·발주사 지연·검수 이견 등 관찰 가능한 신호}
- 에스컬레이션 임계값: {수치·사건}
- 재검토일 또는 트리거: {값}

## 승인
- 판정: APPROVED | CONDITIONAL | REJECTED
- 조건: {없음 또는 Owner·기한·증거}
- 승인자·일시: {이름 · YYYY-MM-DD HH:mm}
- 발주사 합의 근거: {서명·회의록·메일 링크 또는 내부 결정}

## 다음 행동
- {역할}: {행동} — {기한}
```

## 사용 규칙

- 결정 전 근거와 결정 후 결과를 섞지 않는다.
- `Approved` 상태에는 승인자·대상 범위·버전이 반드시 있어야 하고, 발주사와의 합의가 필요한 결정이면 합의 근거 링크가 있어야 한다.
- 새 근거·CR로 결정이 바뀌면 원본을 지우지 말고 `Superseded`와 후속 카드 ID를 연결한다 — 변경 이력 자체가 계약 변경의 증거 사슬이다.
- 발주사 지연으로 촉발된 결정은 지연 사실·통지일을 카드에 남긴다.
- 개인정보·계정·시크릿 값은 기록하지 않는다.
