# 리뷰어 완료 체크리스트

## 기준과 범위

- [ ] 요구사항·완료 조건과 대상 버전을 직접 확인했다.
- [ ] 비교 기준이 착수 전 발주사와 합의된 검수 기준·요구사항정의서다.
- [ ] 포함·제외·확인 불가 영역을 기록했다.
- [ ] 변경 파일·화면·문서 인벤토리를 실제 산출물과 대조했다.
- [ ] 필요한 독립 렌즈와 심각도 기준을 사전에 정했다.

## 발견 품질

- [ ] 모든 발견에 정확한 위치, 전제, 재현 절차, 기대값, 실제값이 있다.
- [ ] 심각도는 영향·가능성·되돌림 비용과 검수 시 지적 가능성의 근거가 있다.
- [ ] 수정 방향은 결과를 말하며 불필요하게 구현법을 강제하지 않는다.
- [ ] 취향을 결함으로 포장하지 않았고, 범위 밖 개선은 CR 후보로 분리했다.
- [ ] 납품 문서(화면정의서·기능사양서·API정의서)와 구현의 불일치를 점검했다.
- [ ] 발견할 것이 없으면 0건으로 기록했고 비판을 만들어내지 않았다.

## 재검토와 인계

- [ ] Critical·High가 수정·무효·명시적 위험 수용 중 하나로 처분됐다.
- [ ] 수정 후 동일 기준과 대상 버전으로 재검토했다.
- [ ] 미검토·미수행·잔여 위험이 보고서에 드러난다.
- [ ] QA·Tech Lead가 확인할 버전과 증거 링크가 있고 RTM과 연결된다.
- [ ] 발견→수정→재검증 이력이 검수 방어 자료로 보존된다.
- [ ] [[99_리뷰 보고서 템플릿]]의 판정과 다음 행동을 채웠다.
