# 증거·재현·수정 기준

> 발견마다 제3자가 같은 결론에 도달할 수 있는 위치·조건·기대값·실제값을 남긴다. 이 형식은 테스트결과서의 PASS/FAIL 형식과 같다 — 내부 리뷰 증거가 그대로 검수 방어 자료가 된다.

## 검토 실행 기록

| 실행 ID | 렌즈 | 대상·버전 | 방법·명령 | 결과 | 증거 링크 |
|---|---|---|---|---|---|
| RV-RUN-001 | | | | 일치 / 불일치 / 확인불가 | |

> 결과 어휘는 **대조 판정**(계약 ↔ 산출물)이다 — QA의 실행 판정(PASS/FAIL)과 구분한다. 실행해야만 확인되는 항목은 "확인불가"로 남기고 QA 케이스 후보로 회부한다.

## 발견 0건 기록

발견이 없을 때도 아래를 채운다.

| 항목 | 작성 |
|---|---|
| 실행한 렌즈·대상 | |
| 직접 확인한 증거 | |
| 미검토·미수행 영역 | |
| 잔여 위험 (검수 시 지적 가능 지점 포함) | |
| 결론 | 발견 0건 / 추가 검토 필요 |

> [!IMPORTANT] 정직한 0건
> 리뷰 품질은 발견 수로 측정하지 않는다. 근거 있는 결함이 없으면 0건이 맞으며, 비판을 발명하는 것이 더 큰 결함이다. 단, 0건 보고가 "검수 통과 보장"은 아니다 — 확인한 범위만 말한다.
