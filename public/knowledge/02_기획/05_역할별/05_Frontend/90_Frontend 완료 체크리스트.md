# Frontend 완료 체크리스트

## 계약·기능

- [ ] 요구사항정의서와 화면정의서(스토리보드)가 화면·상태별로 반영됐다.
- [ ] Backend URL, payload, 상태코드와 실제 구현이 일치한다(API 정의서 기준).
- [ ] 기본·빈·로딩·오류·권한 없음·재시도 상태가 구현됐다.
- [ ] 변경된 모든 줄과 화면이 요구사항 ID로 추적된다(RTM 갱신 가능).
- [ ] 콘솔 오류와 처리되지 않은 Promise 오류가 없다.
- [ ] 화면정의서에 없는 화면·기능은 CR 승인 없이 포함하지 않았다.

## 접근성·반응형

- [ ] 시멘틱 HTML과 텍스트 또는 접근 가능한 이름을 사용했다.
- [ ] 키보드만으로 모든 기능을 사용할 수 있고 포커스가 보인다.
- [ ] 색상 대비가 WCAG AA 이상이다 (본문 ≥4.5:1, UI 컴포넌트 ≥3:1).
- [ ] 320 / 375 / 768 / 1024 / 1440px에서 오버플로가 없다.
- [ ] 터치 타겟이 최소 48×48px이다 (KWCAG·화면정의서 기준).

## 디자인·성능

- [ ] 기존 CSS 변수·디자인 토큰을 사용하고 새 raw color를 만들지 않았다.
- [ ] 이미지에 width·height가 있고 Hero 외 이미지는 지연 로드한다.
- [ ] 애니메이션은 주로 transform·opacity를 사용한다.
- [ ] 대상 URL 스크린샷을 캡처해 승인된 화면정의서·목업과 비교했다.

## 납품·증거·인계

- [ ] 소스코드가 이관 대상 저장소에 반영되고 형상관리 이력이 남았다.
- [ ] 빌드·배포 스크립트만으로 제3자가 빌드를 재현할 수 있다.
- [ ] 실행한 테스트, viewport, URL, 결과와 증거 경로를 기록했다(테스트결과서 입력).
- [ ] 레이아웃 차이와 알려진 제약을 숨기지 않았다.
- [ ] 미수행 검사는 사유와 위험을 적었다.
- [ ] [[99_Frontend Result Card 템플릿]]으로 Tech Lead·QA에 인계했다.
