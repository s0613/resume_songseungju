# 산출물 메타데이터 템플릿

> 역할별 템플릿을 프로젝트 폴더에 복사할 때 아래 정보를 문서 상단에 둔다. 이 메타데이터가 요구사항 ↔ 산출물 ↔ 검수 결과를 잇는 추적표(RTM)의 재료가 된다.

```yaml
---
project: ""
deliverable-id: ""
requirement-ids: []
milestone: ""
role: ""
owner: ""
reviewer: ""
approver: ""
status: draft
version: "0.1"
due-date:
updated:
related: []
---
```

## 필드 규칙

| 필드 | 규칙 |
|------|------|
| `deliverable-id` | 프로젝트 안에서 유일한 ID. 예: `BE-API-003`. RTM에서 이 ID로 추적 |
| `requirement-ids` | 이 산출물이 충족하는 요구사항정의서(SRS)의 요구 ID만 기재 |
| `milestone` | 이 산출물이 납품되는 마일스톤. 예: `설계 완료`, `검수`. 계약 산출물 목록의 전달 시점과 일치 |
| `role` | 직급이 아니라 결과 책임 역할 |
| `owner` | 최종 책임자 한 명 |
| `reviewer` | 내용·품질을 검토하는 사람 또는 역할 (수행사 내부) |
| `approver` | 승인하는 사람 또는 역할. 발주사 검수 대상이면 발주사 승인자(현업 검수자·최종 승인자)를 기재 |
| `status` | `draft`, `review`, `approved`, `deprecated` 중 하나 |
| `version` | 승인 대상과 테스트 대상을 구분할 수 있는 버전. 어느 버전이 검수본인지 판별 가능해야 함 |
| `related` | 입력 문서·결정·테스트·다음 산출물의 위키링크 |

## 본문 공통 블록

```markdown
## 목적과 요구사항

## 확인된 입력

## 가정·확인 필요

## 결정과 근거

## 산출물

## 완료 증거

## 미결·범위 밖·미수행

## 다음 소비자와 요청 행동

## 검토·승인
```

- **목적과 요구사항**에는 이 산출물이 [[외주 개발 산출물]]의 납품 목록 중 어느 항목(요구사항정의서·화면정의서·API정의서·테스트결과서 등)에 해당하는지 명시한다. 어디에도 해당하지 않고 검수·인수인계·책임 경계 어디에도 안 걸리면 작성 필요를 의심한다.
- **미결·범위 밖·미수행**에는 계약 제외(Out of Scope) 항목과 CR로 회부된 요청, 발주사 지연(자료 미제공·결정 지연)으로 인한 미수행을 날짜와 함께 남긴다.
- **완료 증거**는 [[요구사항과 완료 조건]]의 PASS/FAIL 형식 — 검수 서명의 근거가 되는 부분이다.

> [!TIP] 메타데이터 최소화
> 조회·추적에 실제로 쓰지 않는 필드는 추가하지 않는다. 대신 요구사항 연결, 마일스톤, 책임, 상태, 버전, 완료 증거는 생략하지 않는다.
