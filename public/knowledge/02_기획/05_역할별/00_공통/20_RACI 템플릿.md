# RACI 템플릿

> 한 줄 정의
> 역할 목록이 아니라 **납품 산출물별 실행·최종 책임·자문·공유 대상**을 확정하는 표. 외주에서는 수행사 역할과 발주사 역할을 한 표에서 구분한다 — 검수확인서에 누가 서명하는지, 발주사가 무엇을 제공할 책임이 있는지가 빠지면 종료 시점에 분쟁이 된다.

## 기호

| 기호 | 의미 |
|------|------|
| R — Responsible | 직접 작성·실행하는 역할. 여러 명 가능 |
| A — Accountable | 최종 결과를 책임지는 역할. 반드시 한 명 |
| C — Consulted | 결정 전에 의견을 받아야 하는 역할 |
| I — Informed | 결과를 공유받는 역할 |

## 소속 구분 축

모든 행위자는 소속을 명시한다: **수행사** 또는 **발주사**.

| 소속 | 대표 역할 | 전형적 책임 |
|------|-----------|-------------|
| 수행사 | PM·설계·구현·QA·SI 문서화 등 | 산출물 작성(R)·납품 책임(A) |
| 발주사 | 발주 담당 | 자료 제공·의사결정·CR 승인 창구 (R/C) |
| 발주사 | 현업 검수자 | 산출물·기능의 업무 관점 검수 (R of 검수) |
| 발주사 | 최종 승인자 | 검수확인서 서명·잔금 승인 (A of 검수) |

- 검수의 A는 발주사 최종 승인자다 — 수행사가 자기 산출물의 검수 A를 겸하면 검수가 아니라 자기 보고다.
- 발주사 R 항목(자료 제공·계정 발급·결정)도 표에 행으로 넣는다. 표에 없으면 지연 책임을 물을 근거가 없다.

## 충돌 점검

- [ ] 모든 산출물에 A가 정확히 한 명인가?
- [ ] 모든 산출물에 실제로 실행할 R이 한 명 이상인가?
- [ ] 검수 산출물(테스트결과서·검수확인서)의 Approver가 발주사 측인가? 수행사 작성자와 분리됐는가?
- [ ] 발주사 R 항목(자료 제공·결정·검수 피드백)이 기한과 함께 표에 있는가? 지연 시 기록·공지 경로가 있는가?
- [ ] 승인자가 대상 버전과 완료 증거를 직접 확인하도록 되어 있는가?
- [ ] 검수 기간 상한(예: 전달 후 10영업일 내 피드백 없으면 승인 간주)이 계약에 있는가?
- [ ] 휴가·퇴사·장애 시 대리자 또는 인수인계 경로가 있는가? (발주사 담당자 교체 포함)
- [ ] 비활성 역할의 위험을 다른 역할이 명시적으로 인수했는가?
