# Release·운영 기획 가이드

> Release·운영의 임무는 검수를 통과한 버전을 식별 가능한 상태로 운영 환경에 이관·오픈하고, 안정화 기간의 이상을 탐지·복구하며, 발주사 운영 인수와 하자보수 개시 상태를 기록하는 것이다. 외주 프로젝트의 릴리즈는 출시(launch)가 아니라 **검수 후 이관 → 단계 오픈(파일럿→베타→가오픈→오픈) → 안정화 → 하자보수 개시**다.

## 활성화 조건

- 검수 통과본을 발주사 운영 환경 또는 공유 환경으로 이관·배포한다.
- 데이터·스키마·설정·외부 연동이 바뀐다.
- 무중단, 단계 오픈, 유지보수 창 또는 발주사·현업 공지가 필요하다.
- 장애 시 롤백·복구와 사람의 go/no-go 판단이 필요하다.

## 필수 입력

| 입력 | 최소 조건 | 없을 때 |
|---|---|---|
| 릴리즈 후보 | commit·artifact·설정 버전 식별 | 이관 차단 |
| QA 판정·검수 근거 | 대상 버전과 실행 증거 연결, 발주사 검수(UAT)·검수확인서 상태 | 이관 차단 |
| 리뷰·보안 결과 | 차단 발견과 예외 처분 | 사람 위험 승인 필요 |
| 배포·마이그레이션 절차 | Owner, 순서, 예상 시간 | 이관 차단 |
| 롤백·복구 절차 | 트리거, 결정권자, 검증법 | 이관 차단 |
| 모니터링·공지 | 임계값, 안정화 관찰 창, 발주사·현업 연락망 | go/no-go에서 판단 |

## 결정 순서

1. [[01_릴리즈 범위·버전 계획]]에서 포함 변경과 정확한 artifact를 동결한다 — 검수받은 버전과 이관본이 같아야 한다.
2. [[02_Go-No-Go 게이트]]에서 자동 증거와 사람 승인자, 검수·발주사 승인 근거를 확정한다.
3. [[03_배포·마이그레이션 계획]]에 순서·Owner·검증·중단점을 적는다.
4. [[04_롤백·복구 계획]]에서 트리거와 복구 목표를 사전 합의한다.
5. [[05_모니터링·커뮤니케이션]]으로 안정화 관찰 지표·발주사 공지·에스컬레이션을 정한다.
6. [[90_Release·운영 완료 체크리스트]]를 통과한 뒤 사람이 go/no-go를 승인한다.
7. 실행 후 [[99_릴리즈 보고 템플릿]]으로 결과, 운영 인수, 하자보수 개시 상태를 기록한다.

## 산출물과 소비자

| 산출물 | 소비자 | 요청 행동 |
|---|---|---|
| 릴리즈 manifest·게이트 | 사람 승인자 | merge·이관 승인 또는 반려 |
| 배포·롤백 계획 | 실행자·온콜 | 계획대로 실행·감시 |
| 모니터링·공지 계획 | 운영·발주사·현업 | 이상 대응·상태 공유 |
| 릴리즈 보고 | PM·QA·발주사·SI·문서화 | 결과 확인, 운영 인수, 하자보수 개시 확인 |

## 역할 경계

- Release는 QA의 독립 판정이나 Security의 위험 평가를 대신하지 않으며, 발주사 검수를 건너뛰고 오픈하지 않는다.
- 납품·인수 층위: **Release·운영은 시스템 운영 상태의 기술적 이관**, [[00_SI·문서화 기획 가이드|SI·문서화]]는 계약 산출물·자산의 납품, [[00_고객·업무책임 기획 가이드|고객·업무책임]]은 발주사의 인수 확인·서명을 맡는다. **하자보수 개시일의 정본 기록은 [[99_릴리즈 보고 템플릿]]** — SI·문서화와 고객·업무책임 문서는 이 값을 인용한다.
- Release는 미승인·미검수 변경을 이관 범위에 넣거나 완료 조건을 사후 완화하지 않는다. 오픈 준비 중 들어오는 범위 밖 요청은 CR 절차로 회부한다.
- 자동화·에이전트는 증거 수집과 실행을 도울 수 있지만 **merge 승인과 운영 환경 이관 승인은 반드시 지정된 사람이 한다.**
- 비밀값은 문서에 적지 않고 이름·Owner·승인된 저장 위치만 기록한다.

## 진입·종료 게이트

**진입:** 대상 artifact, QA 판정, 발주사 검수·승인 근거, 차단 이슈 처분, 배포·롤백·관찰 계획, 사람 승인자가 준비됐다.

**종료:** 사람이 승인한 정확한 버전이 이관·오픈됐고, 스모크·안정화 관찰 창이 통과했으며, 이상·롤백·공지·운영 인수 결과와 하자보수 개시일이 기록됐다. 이 기록은 인수인계서·완료보고서의 근거로 쓸 수 있어야 한다.
