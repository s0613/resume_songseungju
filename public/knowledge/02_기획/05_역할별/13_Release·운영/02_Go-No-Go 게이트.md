# Go-No-Go 게이트

> 자동 검사 결과와 사람의 책임 승인을 분리해 merge·운영 환경 이관의 최종 결정권을 명확히 한다. 오픈 결정의 근거는 기세가 아니라 **검수 통과와 발주사 합의**다.

## 사전 게이트

| 게이트 | 대상 기준 | 증거 | 결과 | 차단 시 행동 | 확인자 |
|---|---|---|---|---|---|
| 범위·artifact 일치 | [[01_릴리즈 범위·버전 계획]] | | | | |
| 코드·디자인·문서 리뷰 | 차단 발견 0 또는 승인 | | | | |
| CI·자동 테스트 | 필수 작업 PASS | | | | |
| QA | 대상 버전 PASS·승인된 CONDITIONAL | | | | |
| 발주사 검수(UAT) | 승인 또는 조건부 승인(조건 추적 중) | | | | |
| 보안·개인정보 | 오픈 차단 위험 해소 | | | | |
| 운영 준비 | 롤백·관측·온콜 준비 | | | | |

## 사람 승인

| 중요 행동 | 승인 대상 | 사람 승인자 | 승인 시각 | 승인 기록 | 실행자 |
|---|---|---|---|---|---|
| 보호 branch merge | 정확한 PR·commit | | | | |
| 운영 환경 이관·오픈 시작 | release ID·artifact | | | | |
| 데이터 마이그레이션 | script·백업·영향 | | | | |
| 승인된 예외 수용 | 위험·기한·완화책 | | | | |

> [!IMPORTANT] 사람 게이트
> 봇, 에이전트, CI 성공 상태는 승인자가 아니다. 보호 branch merge와 운영 환경 이관은 대상 버전을 확인한 지정 사람이 승인해야 한다.

## Go/No-Go 회의 기록

| 질문 | 답·증거 |
|---|---|
| 지금 오픈하는 근거는? (검수 승인·발주사 합의 링크) | |
| 이번 오픈 단계는? (파일럿/베타/가오픈/오픈) 다음 단계 조건은? | |
| 남은 차단·조건부 항목은? | |
| 실패를 가장 먼저 알려줄 지표는? | |
| 롤백 결정권자와 호출 방법은? | |
| 발주사·현업·운영 공지가 준비됐는가? | |
