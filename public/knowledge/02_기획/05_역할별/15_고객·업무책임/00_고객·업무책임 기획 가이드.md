# 고객·업무책임 기획 가이드

> 고객·업무책임의 임무는 실제 업무 시나리오로 결과를 검수하고, 고객이 해야 할 결정·제공·인수 행동과 조건부 승인·지원 경계를 최종 확정하는 것이다.

## 활성화 조건

- 외부 고객·현업의 UAT, 업무 규칙 승인, 자산 인수 또는 정산 확인이 필요할 때 활성화한다.

## 필수 입력

| 필수 입력 | 최소 조건 |
|---|---|
| 계약·요구사항·완료 조건 | 승인본, 범위 밖, 대상 버전 |
| QA·보안·릴리즈 결과 | 실제 증거와 잔여 위험 — [[99_QA 판정 템플릿]] · [[99_릴리즈 보고 템플릿]] · [[99_SI 납품 확인 템플릿]] |
| UAT 환경·업무 데이터 | 허용된 데이터와 사용자 권한 |
| 산출물·자산 목록 | 문서·소스·계정·라이선스의 Owner |
| 고객 의사결정 구조 | 검수자, 최종 승인자, 대리자 |

## 결정 순서

1. 실제 업무의 성공·예외 시나리오를 확정한다.
2. 고객 행동·자료·접근과 외부 의존을 Owner·기한에 연결한다.
3. 승인·조건부 승인·반려 기준을 합의한다.
4. 자산·계정·운영 자립을 직접 확인한다.
5. 하자보수·지원 경계를 합의하고 최종 인수 기록을 남긴다.

| 산출물 | 소비자 | 요청 행동 |

| UAT 결과·업무 예외 | 구현·QA·PM | 결함 수정 또는 범위 판단 |

## 역할 경계

- 고객·업무책임은 QA를 대신하지 않고 실제 업무 적합성과 인수를 판정한다.
- 납품·인수 층위: Release·운영은 시스템 운영 상태의 기술적 이관, SI·문서화는 계약 산출물·자산의 납품, **고객·업무책임은 발주사의 인수 확인·서명**을 맡는다. 하자보수 개시일은 [[99_릴리즈 보고 템플릿]]의 기록이 정본이다.
- 합의되지 않은 신규 요구를 결함으로 처리하지 않고 변경요청으로 분리한다.
- 조건부 승인은 문제를 숨기는 수단이 아니며 Owner·기한·재검수 조건이 필요하다.
- **비밀번호·토큰·API 키·인증서·복구코드 등 비밀값은 어떤 역할 문서에도 저장하지 않는다.**

## 진입·종료 게이트

**진입:** 승인 요구사항, QA 결과, UAT 환경, 검수자·승인자, 대상 버전이 준비됐다.

**종료:** 핵심 업무 시나리오가 판정됐고, 조건·미해결·Owner Action, 자산 인수, 하자보수·지원 경계가 서명 가능한 기록으로 남았다.
