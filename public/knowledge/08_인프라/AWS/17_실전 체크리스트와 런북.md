# 실전 체크리스트와 런북

> [!NOTE] 사용법
> 모든 항목을 무조건 구현하는 목록이 아니다. 해당 없음은 이유를 기록하고, 프로덕션 위험에 맞는 완료 조건으로 사용한다.

## 신규 계정·랜딩 존

- [ ] 루트 MFA·복구 수단 보호, 액세스 키 없음
- [ ] Organizations/OU와 관리 계정 워크로드 금지
- [ ] IAM Identity Center와 최소 권한 permission set
- [ ] 조직 CloudTrail·Config·중앙 로그 보관
- [ ] GuardDuty/Security Hub 등 위험 기반 보안 서비스
- [ ] 필수 태그, Budget, Cost Anomaly Detection
- [ ] 승인 리전과 SCP 가드레일
- [ ] 보안·로그·네트워크 위임 관리자
- [ ] break-glass 접근과 시험 기록

## 서비스 설계

- [ ] 사용자·데이터·트래픽·지연·성장 가정
- [ ] 데이터 등급·리전·보존·삭제·암호화 요구
- [ ] SLO, RTO, RPO, 예상 장애 모드
- [ ] 최소 2 AZ와 단일 실패점 검토
- [ ] IAM role, SG, VPC endpoint, 공개 접근 근거
- [ ] timeout, retry+jitter, idempotency, backpressure
- [ ] 할당량과 하류 용량 부하 시험
- [ ] 비용 견적과 owner·태그·unit cost
- [ ] IaC, ADR, 데이터 흐름·신뢰 경계 다이어그램

## 배포 전

- [ ] 변경·보안·비용 plan 검토
- [ ] 백업과 실제 복원/롤백 절차 확인
- [ ] DB 호환 migration과 구버전 공존
- [ ] immutable artifact와 digest/version 고정
- [ ] secret·인증서·키·권한 존재 검증
- [ ] 로그·메트릭·트레이스·감사·배포 마커
- [ ] 카나리/블루그린 지표와 자동 중단 조건
- [ ] 사람 승인과 담당자·연락망
- [ ] 배포 후 10분 집중 관측

## 월간 운영

- [ ] OS·컨테이너·런타임·라이브러리 취약점과 패치
- [ ] 미사용 권한·키·역할·외부 공유 Access Analyzer 검토
- [ ] 백업 성공이 아닌 표본 복원 시험
- [ ] SLO·알람 오탐·incident action item 검토
- [ ] 비용 이상·미사용 자원·권리 크기·약정 활용률
- [ ] Service Quotas·인증서·도메인·비밀 만료
- [ ] Config drift와 콘솔 변경
- [ ] 로그 보존·PII·수집 비용

## 장애 런북 템플릿

```markdown
# {알람/장애명}
- Owner:
- Severity:
- User impact:
- Dashboard:
- Last known good deployment:

## 1. 확인
- 알람이 실제 사용자 실패와 일치하는가?
- 영향 리전/AZ/버전/고객 범위는?

## 2. 즉시 완화
- 최근 배포 롤백 / feature flag off
- 트래픽 제한 / queue buffer / failover
- 손상 자격 증명 폐기 / 리소스 격리

## 3. 검증
- SLI 정상화
- 데이터 정합성
- backlog 소진과 재발 여부

## 4. 후속
- 타임라인, 근본 원인, 탐지·런북·테스트 개선
```

## 비용 폭주 즉시 대응

1. Cost Explorer와 CloudTrail로 계정·리전·서비스·API·리소스를 특정한다.
2. 침해 가능성이 있으면 비용 문제보다 보안 사건 절차를 우선한다.
3. 신규 생성·확장을 SCP/권한/서비스 설정으로 제한하되 프로덕션 영향을 확인한다.
4. 오토스케일, 무한 재시도, 로그 폭주, NAT/egress, 키 유출을 점검한다.
5. 중지 후 Budget·quota·rate limit·idempotency·탐지를 개선한다.
