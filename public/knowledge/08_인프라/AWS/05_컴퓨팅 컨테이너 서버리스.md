# 컴퓨팅·컨테이너·서버리스

> 한 줄 정의
> 실행 시간, 상태, 트래픽 모양, 격리, 이식성, 팀 운영 능력에 따라 가장 단순한 컴퓨팅 추상화를 고른다.

## 선택표

| 선택 | 잘 맞는 경우 | 고객이 운영할 것 |
|---|---|---|
| Lambda | 짧은 이벤트 처리, 급격한 탄력성, 유휴 시간 큼 | 코드, 의존성, 동시성, 타임아웃 |
| App Runner | 표준 웹 컨테이너를 최소 운영으로 공개 | 앱·이미지·오토스케일 |
| ECS + Fargate | 컨테이너, Kubernetes 불필요, 서버 관리 최소화 | Task/Service, 네트워크, 이미지 |
| ECS + EC2 | 컨테이너와 인스턴스 비용·성능 제어 | 위 항목 + 인스턴스·패치·용량 |
| EKS | Kubernetes 생태계·표준 API가 실제 요구 | 클러스터 애드온, 노드, K8s 운영 |
| EC2 | OS·에이전트·GPU·특수 네트워크 완전 제어 | OS부터 애플리케이션까지 |
| Lightsail | 작은 고정형 웹·학습·간단한 VPS | 제한된 범위의 서버 운영 |
| Batch | 대규모 큐 기반 배치 | 작업 정의·큐·컴퓨팅 환경 |

> [!TIP] 기본 판단
> 이벤트 함수면 Lambda, 일반 컨테이너면 ECS Fargate, Kubernetes 요구가 검증됐으면 EKS, OS 제어가 필요하면 EC2에서 시작한다.

## EC2 핵심

- 인스턴스 패밀리: 범용, 컴퓨팅, 메모리, 스토리지, 가속 컴퓨팅. 벤치마크로 결정한다.
- Auto Scaling Group은 최소·희망·최대 용량과 상태 확인을 관리한다.
- ALB는 HTTP/HTTPS L7, NLB는 고성능 TCP/UDP/TLS L4, GWLB는 네트워크 어플라이언스에 적합하다.
- EBS는 인스턴스와 별도 수명의 블록 스토리지, instance store는 빠르지만 임시 데이터다.
- 시작 템플릿, AMI 파이프라인, SSM Patch Manager로 불변 인프라에 가깝게 운영한다.
- 구매: On-Demand로 기준 측정 → 지속 베이스로드 Savings Plans → 중단 가능 작업 Spot.

## ECS·EKS·Fargate

- ECR에 이미지를 저장하고 이미지 digest 고정, 취약점 스캔, 수명주기 정책을 설정한다.
- ECS Task Role과 Task Execution Role을 구분한다.
- Fargate는 호스트 운영을 줄이지만 단위 가격과 지원 기능을 확인한다.
- EKS는 control plane만 관리형이다. 노드·CNI·CSI·Ingress·업그레이드·정책·관측은 여전히 운영 대상이다.
- Kubernetes 이식성이 목표여도 AWS 연동(ALB, EBS, IAM, Route 53)을 쓰면 완전한 이동성은 생기지 않는다.

## Lambda 실전

- 함수는 무상태로 설계하고 상태는 DynamoDB, S3, SQS 등 외부에 둔다.
- 재시도와 중복 실행을 전제로 idempotency key를 사용한다.
- 예약 동시성은 보호 장치이자 격리 장치다. 하류 DB 연결 수를 기준으로 제한한다.
- VPC 연결은 필요한 경우만 사용하고, RDS 연결 폭증에는 RDS Proxy를 검토한다.
- 비동기 실패 목적지·DLQ, 타임아웃, 메모리, 임시 스토리지, 로그 보존을 명시한다.
- 긴 실행·상시 연결·무거운 초기화는 컨테이너가 더 단순할 수 있다.

## 오토스케일 불변식

1. CPU만 보지 말고 queue depth, request count, concurrency 같은 수요 지표를 쓴다.
2. scale-out 속도와 하류 서비스 용량을 함께 설계한다.
3. scale-in 때 연결 종료와 작업 완료 시간을 보장한다.
4. 부하 시험으로 할당량, 콜드스타트, 이미지 시작 시간, DB 연결 상한을 검증한다.
