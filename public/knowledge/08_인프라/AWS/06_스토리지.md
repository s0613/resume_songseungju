# 스토리지

> 한 줄 정의
> 접근 방식이 object·block·file 중 무엇인지 먼저 결정하고, 성능·내구성·수명주기·복구·전송 비용을 함께 설계한다.

## 선택표

| 유형 | 서비스 | 잘 맞는 경우 |
|---|---|---|
| Object | S3 | 업로드, 백업, 정적 자산, 데이터 레이크 |
| Block | EBS | EC2의 부팅·DB·낮은 지연 블록 장치 |
| Ephemeral block | EC2 instance store | 캐시·스크래치·복제된 임시 데이터 |
| Shared file | EFS | Linux NFS 공유 파일, 탄력 용량 |
| Managed file | FSx 계열 | Windows, Lustre, NetApp ONTAP, OpenZFS |
| Hybrid | Storage Gateway | 온프레미스와 S3/파일/테이프 연계 |
| Transfer | DataSync, Transfer Family, Snow Family | 온라인·프로토콜 기반·오프라인 대량 이동 |
| Backup | AWS Backup | 계정·서비스 통합 백업 정책과 보관 |

## S3 핵심

- 버킷은 리전 리소스이고 객체는 key와 version으로 식별한다.
- 새 버킷은 퍼블릭 액세스 차단을 기본값으로 유지한다.
- ACL보다 bucket policy와 IAM을 우선하고 Object Ownership을 명확히 한다.
- Versioning, 수명주기, 복제, Object Lock은 서로 다른 목적이다.
- SSE-S3 또는 SSE-KMS를 사용하고 KMS 권한과 비용을 함께 본다.
- presigned URL은 제한 시간·행위·객체에만 권한을 위임한다.
- 대용량 업로드는 multipart, 정적 배포는 S3 직접 공개보다 CloudFront OAC를 쓴다.

### 스토리지 클래스

| 패턴 | 후보 |
|---|---|
| 빈번한 접근 | S3 Standard |
| 접근 패턴 미확정·변동 | Intelligent-Tiering |
| 비빈번하지만 즉시 접근 | Standard-IA |
| 재생성 가능·단일 AZ 허용 | One Zone-IA |
| 아카이브 | Glacier Instant/Flexible/Deep Archive |

최소 보관 기간, 검색 비용, 복원 시간을 확인한다. Lifecycle 전환이 항상 싸지는 않다.

## EBS·EFS

- EBS 볼륨과 스냅샷 암호화, 삭제 시 동작, AZ 복구 절차를 IaC에 명시한다.
- gp3는 일반 목적 기본 후보이며 IOPS·처리량을 용량과 독립 조정할 수 있다.
- 데이터베이스는 필요한 IOPS·지연을 측정하고 io 계열을 검토한다.
- EFS는 다중 AZ 공유가 편하지만 작은 파일·메타데이터 집약 작업 성능을 시험한다.
- 파일 권한, access point, throughput mode, lifecycle class를 명시한다.

## 보호와 수명주기

1. 데이터 등급과 소유자
2. 암호화 키와 접근 정책
3. 버전·백업·복제 중 필요한 보호
4. 보존·법적 보류·삭제 정책
5. 복원 시험과 RTO/RPO
6. 데이터 전송·요청·KMS·검색 비용

> [!WARNING] 복제는 백업이 아니다
> 잘못된 삭제·암호화·애플리케이션 오류도 복제될 수 있다. 변경 불가능한 별도 복구 지점을 둔다.
