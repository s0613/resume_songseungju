# 마이그레이션과 하이브리드

> 한 줄 정의
> 이전은 서버 복사가 아니라 애플리케이션·데이터·네트워크·운영 책임을 단계적으로 바꾸는 프로그램이다.

## 7R 전략

| 전략 | 의미 | 판단 |
|---|---|---|
| Retire | 폐기 | 사용·가치 없는 시스템 |
| Retain | 유지 | 규제·의존성·우선순위로 당장 이동 안 함 |
| Rehost | lift-and-shift | 빠른 이전, 기술 부채 유지 |
| Relocate | 플랫폼 변경 없이 대규모 위치 이동 | 지원 플랫폼에 한정 |
| Replatform | 일부 관리형 전환 | 코드 변화 제한, 운영 절감 |
| Repurchase | SaaS/새 제품으로 교체 | 프로세스·데이터 전환 필요 |
| Refactor | 클라우드 네이티브 재설계 | 가치와 투자 모두 큼 |

모든 앱을 refactor하지 않는다. 비즈니스 가치, 남은 수명, 위험, 일정으로 포트폴리오별 전략을 고른다.

## 주요 도구

| 단계 | 서비스 |
|---|---|
| 평가·포트폴리오 | Migration Hub, Application Discovery Service |
| 서버 이전 | Application Migration Service(MGN) |
| DB 평가·이전 | DMS, Schema Conversion Tool/관련 변환 도구 |
| 대량 데이터 | DataSync, Transfer Family, Snow Family |
| 네트워크 | Site-to-Site VPN, Direct Connect, Transit Gateway |
| 하이브리드 실행 | Outposts, ECS Anywhere, EKS Anywhere, Systems Manager |
| VMware | AWS 지원 VMware 옵션은 현재 제공 상태·전략을 공식 확인 |

## 웨이브 계획

1. 자산, 호출 관계, 데이터 흐름, 사용량, 소유자, 폐기 후보를 발견한다.
2. 랜딩 존, IAM, 네트워크, DNS, 로그, 보안, 비용 배부를 먼저 준비한다.
3. 낮은 위험의 파일럿으로 도구·런북·시간 추정을 검증한다.
4. 의존성이 함께 움직이는 migration wave를 만든다.
5. 동기화, 정합성 검증, cutover, rollback, hypercare를 리허설한다.
6. 이전 후 권리 크기·관리형 전환·라이선스·폐기까지 완료한다.

## 데이터 이전

- online/offline, 초기 적재/CDC, 허용 중단 시간, 데이터 크기와 변경률을 구분한다.
- 체크섬·행 수·업무 합계·샘플 쿼리로 정합성을 검증한다.
- 원본과 대상의 동시 쓰기 기간은 충돌과 진실의 원천을 명확히 한다.
- cutover 뒤 원본을 즉시 삭제하지 말고 합의된 rollback window 동안 읽기 전용 보존한다.

## 하이브리드 운영

- VPN은 빠른 시작과 백업, Direct Connect는 예측 가능한 전용 연결에 적합하다.
- BGP, 경로 전파, 겹치는 CIDR, MTU, DNS 전달, 방화벽, 비대칭 라우팅을 시험한다.
- 클라우드와 온프레미스의 시간 동기화, 인증, PKI, 프록시, 로그 상관관계를 맞춘다.
- 양쪽 운영 도구를 무기한 이중 유지하지 않도록 목표 운영 모델을 정한다.

> [!WARNING] 철수 완료 조건
> 클라우드에서 켜졌다고 마이그레이션 완료가 아니다. 원본 폐기, 라이선스 종료, 백업·관측 전환, CMDB·런북·담당자 갱신까지 끝나야 한다.
