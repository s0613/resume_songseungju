# 생성·그라운딩 전략 카탈로그

> 마지막 단계의 목표는 하나 — 모델이 **컨텍스트 밖을 말하지 못하게** 하고, 말한 것은 **검증 가능하게** 만든다. 원리는 [[Grounding]]·[[Context Engineering]] — 여기는 선택지 카탈로그다.

## 그라운딩 강제 전략

| 전략 | 원리 | 비고 |
|------|------|------|
| 거절 규칙 | "근거에 없으면 모른다고 답하라"를 명시 | 기본값 — 거절률도 지표로 감시(과잉 거절도 실패다) |
| 인용 강제 | 문장·문단마다 근거 청크 ID/출처 표기를 요구 | 검증 가능성의 핵심 — 출처는 파싱 메타데이터에서 → [[문서 수집과 파싱]] |
| 구조화 출력 | {답, 근거 ID 목록, 확신도}를 JSON으로 분리 | 후처리 검증·UI 출처 표시가 쉬워진다 |
| 인용-근거 대조(citation verification) | 생성 후 각 인용이 실제로 근거를 지지하는지 후처리 검사 | "있는 문서, 없는 내용" 환각 인용 탐지 → [[Hallucination Detection]] |
| Chain-of-Verification | 초안 → 검증 질문 생성 → 재확인 → 수정 | 호출 수가 배수로 늘어 고가치 답변만 |

## 다문서·장문 처리 전략

| 전략 | 원리 | 언제 |
|------|------|------|
| Stuff | 후보 전부를 한 컨텍스트에 | 기본값 — 예산 안이면 이것이 최선 |
| Map-Reduce | 문서별 부분 답 → 종합 | 예산 초과·병렬 가능할 때. 종합 단계의 정보 소실 주의 |
| Refine | 문서를 순회하며 답을 점진 수정 | 순서 의존·지연 큼 — 드물게 |

## 컨텍스트 조립 전략

- **문서 구분자·출처 헤더**를 청크마다 명시 — 모델이 어디부터 어디까지가 근거인지 알게 한다.
- **배치**: 핵심 근거를 앞 또는 양 끝에 ([[리랭킹·압축 전략 카탈로그]]의 재배열).
- **예산 배분 고정**: 시스템 지시·근거·대화 이력의 토큰 배분을 정하고, 넘치면 이력부터 줄인다 → [[Context Engineering]].
- **모순 근거 우선순위 규칙**: 발효일·권위 기준을 프롬프트에 명시 → [[실시간 지식 파이프라인]].

## 선택 가이드

1. **시작**: 거절 규칙 + 출처 헤더 + stuff. 인용 강제는 UI가 출처를 보여줄 수 있게 되는 즉시.
2. faithfulness가 낮게 측정되면 프롬프트 강화보다 먼저 **조립 실패**(근거가 잘리거나 묻힘) 여부부터 확인 → [[RAG 실패 진단과 개선]].
3. 검증 계열(CoVe·인용 대조)은 비용이 크다 — 고위험 도메인(의료·법률·금융)부터.
