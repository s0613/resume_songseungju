# 검색 전략 카탈로그

> 검색 개선의 두 방향 — **질의를 고치거나**(query side), **찾는 방식을 고치거나**(retrieval side). 총론은 [[Query Transformation]]·[[Hybrid Retrieval]] — 여기는 선택지 카탈로그다.

## 질의 측 전략 — 질의와 문서의 표현 격차 줄이기

| 전략 | 원리 | 언제 쓰나 |
|------|------|----------|
| Query Rewriting | 구어·오타·모호함을 검색형 문장으로 재작성 | 대화형 입력 전반 — 대화 맥락의 대명사 해소 포함 |
| Multi-Query | 질의를 여러 변형으로 만들어 병렬 검색 후 합집합 | 재현율이 아쉬울 때의 저비용 1수 |
| HyDE | 가설 답변 문서를 LLM으로 생성해 그것을 임베딩·검색 | 질의는 짧고 문서는 길어 표현이 비대칭일 때 |
| Step-back | 구체 질문을 상위 개념 질문으로 바꿔 배경 검색 병행 | 원리·규정이 필요한 구체 사례 질문 |
| Decomposition | 복합 질문을 하위 질문들로 분해해 각각 검색 | 멀티홉·비교 질문 — 반복형은 [[Agentic RAG]] |
| Self-query(필터 추출) | 자연어에서 필터 조건(날짜·유형)을 구조화 추출 | "작년 3분기 보고서에서…" 류 |
| Routing | 질의를 분류해 인덱스·검색기를 선택 | 코퍼스가 여러 개일 때(제품 문서 vs 사내 규정) |

## 검색 측 전략 — 후보를 만드는 방식

| 전략 | 원리 | 언제 쓰나 |
|------|------|----------|
| [[Hybrid Retrieval]] + RRF | dense+[[BM25]] 결과를 Reciprocal Rank Fusion으로 병합 | 품질 우선 환경의 기본값 |
| 메타데이터 필터 검색 | 필터로 후보를 좁힌 뒤 벡터 검색 | 권한(ACL)·시점·문서유형 제약 — recall 회귀 확인 필수 |
| MMR | 관련성과 후보 간 다양성을 함께 최적화 | top-k가 비슷한 청크로 도배될 때 |
| 반복·재귀 검색 | 1차 결과를 읽고 다음 검색을 다시 계획 | 멀티홉 — 지연 비용 큼 → [[Agentic RAG]] |
| 시간 가중 검색 | 유사도 점수에 recency 보정 | 공지·정책처럼 최신이 이겨야 하는 도메인 → [[실시간 지식 파이프라인]] |
| Ensemble | 서로 다른 검색기 여러 개를 병렬 실행 후 융합 | 단일 방식의 사각을 상호 보완 |

## 선택 가이드

1. **순서**: 하이브리드+RRF부터 → 그래도 안 잡히는 질의 유형을 로그에서 분류 → 그 유형에 맞는 질의 측 전략을 하나씩 추가.
2. 질의 측 전략은 전부 **LLM 호출 = 지연·비용**을 산다 — 모든 질의에 걸지 말고 라우팅으로 필요한 질의에만.
3. 융합 가중치·k값 변경도 골든셋 회귀 대상이다 → [[RAG 실패 진단과 개선]].
