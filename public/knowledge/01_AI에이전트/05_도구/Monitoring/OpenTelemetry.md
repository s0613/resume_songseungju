# OpenTelemetry

> CNCF 산하의 오픈소스 관측성 표준·프레임워크. 트레이스·메트릭·로그를 벤더 중립적으로 수집·전송하는 표준 API와 SDK, 컬렉터를 제공한다.

## 특징
- **세 가지 신호**: 분산 트레이싱(trace/span), 메트릭, 로그를 하나의 표준으로 다룬다.
- **벤더 중립**: 코드 계측은 표준 API로 한 번만 하고, 백엔드(Jaeger, Grafana, Datadog, Langfuse, Arize 등)는 OTLP 프로토콜로 자유롭게 교체한다.
- **Collector**: 텔레메트리를 수집·가공·라우팅하는 독립 컴포넌트로 파이프라인을 유연하게 구성한다.
- **GenAI 시맨틱 컨벤션**: LLM 호출(모델, 토큰, 프롬프트 등)을 위한 표준 속성 규약이 정의되고 있어 LLM 관측성에도 적용된다.

## 에이전트에서의 활용
- 에이전트 실행 루프를 span으로 계측하면 LLM 호출·도구 사용·리트리벌의 분산 트레이스를 표준 형식으로 남길 수 있다.
- Langfuse, Arize/Phoenix 등 OpenTelemetry 호환 백엔드로 동일한 계측을 전송해 도구 종속을 피한다.
- 애플리케이션의 일반 인프라 텔레메트리와 LLM 텔레메트리를 같은 파이프라인에서 통합 관측한다.

## 장단점
- **장점**: 업계 표준, 벤더 비종속, 다양한 백엔드·언어 SDK 지원, 인프라+LLM 신호 통합.
- **단점**: 그 자체는 시각화·평가 UI가 아니라 수집·전송 표준이므로 별도 백엔드가 필요하다. 초기 계측 설정에 학습 비용이 든다.

## 언제 쓰나
- 특정 관측성 벤더에 묶이지 않는 표준 계측 기반을 깔고, 백엔드는 자유롭게 선택·교체하고 싶을 때.
